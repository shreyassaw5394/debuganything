Questions.

Is it safe to point at my app?

It only looks. It never kills, signals, patches or sets breakpoints, never uses sudo, caps each tool at 60 s and 50 MB, sends the agent at most 16 KB, scrubs tokens and keys, and asks every time before a packet capture. Nothing leaves your machine. Only observe systems you own or are allowed to debug. Safety details.

Does it need root?

Most tools don't. When one does, Debug Anything prints the exact command for you to run, then reads the file with debuganything import. It never escalates on its own.

Can I use it without an AI agent?

Yes. debuganything why 12345 --symptom slow attaches, runs the right tools and prints ranked findings. Or paste tool output into the analyzer.

How does my team use it?

debuganything init commits the agent config and a rule to the repo, so every teammate's agent has it. Fixes carry run ids in pull requests, and CI can fail a job when memory grows. Workflow guide.

What do the two skills do?

debug-anything tells your agent when to look: a hang, a busy port, an out-of-memory kill, or you saying “slow”. inspect-product audits a whole product as a new user and reports findings with reproductions. npx debuganything setup installs both.

How sure are the findings?

Each finding says whether it was observed or inferred and lists what the tools could not see. They are automated diagnostics, not professional advice: read the evidence before you act on it.

Ask it why.

The command attaches, picks the tools for the symptom, writes a report and detaches. Set it up for your agent with npx debuganything setup, or run it yourself.
